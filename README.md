# ieumdesk

**한국어** | [English](README.en.md)

고객사·담당자·영업·견적·업무·고객지원을 연결하는 CRM입니다. React + TypeScript + Express + PostgreSQL로 구현했습니다.

## 로컬 실행

Node.js 22.12 이상이 필요합니다.

```sh
npm ci
cp .env.example .env
npm run dev
```

새로 설치한 환경의 기본값은 합성 데이터를 사용하는 `demo` 모드입니다. 기존 `.env`가 있다면 덮어쓰지 말고 필요한 설정만 반영하세요.

- 웹 화면: http://127.0.0.1:5173
- 같은 로컬망의 다른 PC·휴대폰: `http://실행한-PC의-로컬망-IP:5173` (예: `http://192.168.0.10:5173`)
- API: http://127.0.0.1:3001
- 최초 접속에서 관리자 계정을 직접 만듭니다. 기본 계정·비밀번호는 제공하지 않습니다.
- 이후 가입자는 승인 대기 상태이며 관리자가 역할과 활성 상태를 관리합니다.
- 데모 자료와 암호화 키는 Git에서 제외한 `.local/`에 생성됩니다.

`npm run dev`는 웹 서버를 로컬망에서도 열며, 실행한 PC에 할당된 사설 IPv4 주소(`10.*`, `172.16.*`–`172.31.*`, `192.168.*`)와 로컬 주소만 허용합니다. PC의 네트워크 설정에서 로컬망 IP를 확인하세요. IP가 바뀌면 새 주소로 접속해야 합니다. 다른 기기에서 연결되지 않으면 같은 네트워크에 연결되어 있는지와 실행 PC 방화벽의 TCP 5173 허용 여부를 확인하세요. 게스트 Wi-Fi의 기기 간 통신 차단도 영향을 줍니다.

API는 `127.0.0.1:3001`에서만 수신하고 웹 서버의 `/api` 프록시를 통해 연결되므로, 다른 기기도 웹 주소의 5173 포트만 사용합니다. 기존 로그인·권한·요청 출처 검사는 유지됩니다. 로컬망 접속은 HTTP이므로 신뢰하는 네트워크에서 사용하세요. 인터넷 공개용 HTTPS·도메인 등 배포 설정은 별도로 필요하며 `NODE_ENV=production` 시작은 현재 차단되어 있습니다.

이 PC에서만 접속하도록 되돌리려면 실행 중인 서버를 종료한 뒤, 터미널 두 개에서 각각 `npm run dev:server`와 `npm run dev:client -- --host 127.0.0.1`을 실행하세요.

## 화면 언어

로그인 화면이나 상단 메뉴의 언어 선택에서 **한국어** 또는 **English**를 선택할 수 있습니다. 선택한 언어는 브라우저에 저장되어 새로고침 후에도 유지됩니다. 언어를 바꿔도 현재 페이지와 작성 중인 폼 입력은 유지됩니다.

메뉴·폼·안내·검증 메시지와 날짜 표시는 선택한 언어를 따릅니다. 고객명·메모·첨부파일 등 사용자가 입력한 자료는 원문으로 표시합니다. 서버에 저장되는 상태값·금액·API 요청은 바뀌지 않으며 금액 단위는 원화(KRW)를 유지합니다.

## 화면 표시 이름

관리자는 **환경설정 → 표시 및 메뉴 → 화면 표시 이름**에서 브랜드명과 워크스페이스명을 변경할 수 있습니다. 기본값은 `ieumdesk`와 `Workspace`이며, 각 이름은 최대 60자입니다. 저장한 이름은 로그인·회원가입 화면과 전체 사용자의 사이드바에 적용되고, 브랜드명은 브라우저 제목·하단·도움말에도 표시됩니다. 로그인 전에는 두 표시 이름만 조회할 수 있으며 나머지 환경설정은 인증이 필요합니다. 입력한 문구는 언어 전환 시 번역하지 않습니다.

기존 설치는 보호 옵션과 메뉴 설정을 유지하며 새 표시명의 기본값을 사용합니다. 기존 PostgreSQL의 JSON 설정을 그대로 확장하므로 별도의 스키마 변경은 필요하지 않습니다.

## 주요 기능

### 비밀번호 초기화 (SMTP 불필요)

- 사용자: 로그인 화면의 **비밀번호를 잊으셨나요?**에서 가입 이메일로 초기화를 요청합니다. 등록 여부와 무관하게 같은 접수 안내를 표시합니다. 관리자에게 연락해 본인 확인 후 링크를 받아 새 비밀번호를 설정합니다.
- 관리자: **사용자 관리 → 비밀번호 초기화 요청**에서 요청을 확인하거나, 요청 없이도 대상 사용자의 **비밀번호 초기화**를 선택합니다. 관리자 본인의 비밀번호를 확인한 뒤 발급한 링크를 기존에 확인된 연락처로 직접 전달합니다. 요청 자체는 본인 확인의 증거가 아닙니다.
- 링크는 30분 동안 한 번만 사용할 수 있고 재발급하면 이전 링크는 무효화됩니다. 서버에는 토큰의 해시만 보관하며, 관리자가 창을 닫으면 링크 원문을 다시 조회할 수 없습니다. 링크 발급은 감사 기록에 남습니다.
- 새 비밀번호 저장 시 기존 비밀번호와 모든 로그인이 무효화됩니다. 승인 대기 상태와 권한은 유지되며 이용 중지 계정에는 발급할 수 없습니다. 비밀번호·이메일·권한·상태 변경도 기존 링크를 무효화합니다.
- 로그인 가능한 사용자는 **내 계정 → 비밀번호 변경**을 이용할 수 있습니다. 유일한 관리자가 비밀번호를 분실한 경우 이 흐름을 승인할 다른 관리자가 없으므로 별도 운영 복구가 필요합니다.

기존 PostgreSQL 설치에는 서버 재시작 전에 다음 추가 마이그레이션이 필요합니다. 기존 계정·비밀번호·세션을 수정하지 않고 요청·토큰 테이블만 생성합니다. `demo` 저장소는 자동으로 호환됩니다.

```sh
npx tsx scripts/migrate-features.ts 016_password_reset.sql
npx tsx scripts/migrate-features.ts 016_password_reset.sql --apply
```

적용 전 기존 백업 절차를 따르고, 스키마가 추가된 뒤 새 백업을 생성하세요. 기존 백업은 스키마 일치 검사 때문에 바로 복원할 수 없을 수 있습니다. 앱을 이전 버전으로 되돌릴 때 추가 테이블은 유지해도 됩니다. 이미 사용자가 변경한 비밀번호를 과거 값으로 복원하지 마세요.

| 화면          | 기능                                                  |
| ------------- | ----------------------------------------------------- |
| 업무 현황     | 고객 현황, 만료 예정 계약, 진행 중 업무               |
| 고객사·담당자 | 검색·필터·정렬, 등록·수정, 관계와 연락 이력           |
| 활동·TASK     | 상담·미팅·메모, 담당자·기한·진행 상태                 |
| 영업·견적     | 영업 단계, 예상매출, 품목·할인 계산, 승인·인쇄        |
| 설치 관리     | 설치·접근·서버·연동 정보, 상세 편집, 암호화 첨부      |
| 고객지원      | 문의·공지·답변·댓글, 처리 상태, 첨부·휴지통           |
| 환경설정      | 역할·권한, 보호정보 마스킹, 메뉴·상품·코드, 백업 관리 |

담당자는 관리자와 동일하게 CRM 업무를 관리하며, **사용자 및 권한·환경설정**은 관리자만 사용할 수 있습니다. 환경설정에 포함된 상품·코드 관리, 전체 휴지통 조회·복원, 백업 관리도 관리자 전용입니다. 조회 전용은 업무를 수정할 수 없습니다. 보호정보 원문 조회와 다운로드는 전역 보호 설정을 따릅니다.

## 데이터와 PostgreSQL

`CRM_DATA_MODE=demo`는 `.local/`의 합성 저장소를, `CRM_DATA_MODE=postgres`는 PostgreSQL의 전용 스키마를 사용합니다. PostgreSQL 연결이나 필수 스키마 검증이 실패하면 데모로 자동 전환하지 않습니다.

DB 접속정보는 개인 `.env` 또는 프로세스 환경에 다음 중 하나로 지정합니다.

- `DATABASE_URL`: 연결 문자열 전체를 명시합니다. 대상 DB 이름을 포함해 다른 DB 설정보다 우선합니다.
- `DB_INFO_FILE`: 서버에서 읽을 비공개 JDBC properties 파일 경로입니다. `jdbc.url`, `jdbc.username`, `jdbc.password`를 사용하며 파일은 저장소에 커밋하지 않습니다.

현재 DB·스키마 식별자는 기존 코드와의 호환을 위해 `yeta_crm` 및 `yeta_crm_private`를 사용합니다. `CRM_DATABASE`는 properties 파일 방식의 대상 DB 이름만 재정의합니다.

`db/`에는 스키마 정의, `scripts/`에는 명시적으로 실행하는 DB 준비·스키마 적용·저장 형식 전환·암호화·백업 도구가 있습니다. 서버 시작 시 DB 마이그레이션을 자동 실행하지 않습니다. 스키마 간 의존성이 있으므로 SQL 파일 전체를 번호순으로 일괄 실행하지 마세요. 저장 암호화 전환은 `scripts/encrypt-storage.ts`의 계획·검증·적용 절차를 사용합니다.

운영 데이터가 있는 환경에서 DB 준비·저장 형식 전환·복원 도구를 실행하기 전에는 대상과 사전 조건, 백업 및 복구 절차를 검토해야 합니다.

## 개발 명령

```sh
npm run build
```

- `npm run build`: TypeScript 검사와 Vite 번들 생성
- `npm start`: API만 실행
- `npm run db:inspect`: 설정된 DB의 메타데이터 확인
- `npm run format`: 코드 포맷 정리

실제 PostgreSQL·외부 연동·운영 배포는 빌드와 별도로 검증해야 합니다. 비밀번호 초기화는 관리자 확인·링크 전달 방식이며, 이메일 인증·자동 메일 발송·SSO·푸시 발송, 외부 시스템 접속·원격 업데이트는 연결되지 않았습니다. 백업 스케줄러는 애플리케이션 실행 중 동작하며 외부 보관·키 복구는 별도로 준비해야 합니다.

## 구성

- `src/`: React 화면, 클라이언트 로직과 UI 번역
- `server/`: API, 인증·권한, 저장소, 암호화·백업
- `db/`: PostgreSQL 스키마 정의
- `scripts/`: DB 준비·스키마 적용·암호화·백업 관리 도구
